# ADR NNNN: <short, present-tense decision>

| Field | Value |
|---|---|
| Status | Proposed, Accepted, Superseded or Deprecated |
| Date | YYYY-MM-DD |
| Repo scope | octo-pod, or named interfaces to other repositories |
| Supersedes | ADR-NNNN, or none |
| Superseded by | ADR-NNNN, or none |
| Related | Local ADRs and linked GOAT ADRs, with their status checked |

## TL;DR (for a layperson)

One paragraph without jargon: what is decided, why an operator should care, and what
would change if a different option were chosen.

## Context

The constraint, concrete problem and prior state. Distinguish implemented mechanisms
from proposed policy and deployment acceptance.

## Decision

The choice, specific enough to implement. Name the component boundaries and ownership.

## Alternatives considered

Describe each rejected option fairly and explain why it was rejected.

## Consequences

**Positive.** What gets easier or safer.

**Negative.** Costs, residual risks and remaining obligations.

## Security assessment view

State the security boundary, evidence and residual risk. Link applicable waivers or
control mappings where they exist; do not invent approval, compliance or accreditation.

## Trigger conditions for revisit

Observable changes that require reconsidering this decision.
